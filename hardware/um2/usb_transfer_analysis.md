# USB transfer analysis

## Evidence

- `device_descriptors.bin` is the captured 1209-byte sysfs descriptor blob. `device_descriptors.json` is generated by `scripts/parse_descriptors.py`; the parser checks descriptor lengths/bounds, declared interface count, and per-alt endpoint counts. `device_descriptors.txt` is the complete `lsusb -v` output, obtained with host USB access.
- The device enumerated on bus 001, device 006, port path `1-2`, full speed (12 Mbps), EP0 max packet 8, VID:PID 08bb:2902, one config, wTotalLength 1191, four interface numbers.
- Interface 2 is capture AS, endpoint 0x84 IN, isochronous, interval 1. Its alternate 1 advertises stereo S16_LE 48 kHz. The binary descriptor yields `wMaxPacketSize=0x00c4`, i.e. 196 bytes; ALSA stream status independently reports current playback packet size 192 bytes for playback interface 1 alt 1. Endpoint 0x84 is not active during this observation.
- Capture alt 10 advertises mono S16_LE 16 kHz and a 34-byte endpoint maximum. All 18 capture alternate settings are enumerated in `audio_stream_profile.json` and the raw descriptor dump.
- Playback was already running at stereo S16_LE 48 kHz when first inspected; capture was stopped. The subsequent ALSA parameter query also opened capture, as described below. Playback was left running.

## Host capture / usbmon

Read-only inspection of `/sys/kernel/debug/usb/usbmon/1u` failed with `Permission denied`; debugfs is mounted read-only in this environment. No transfer-level URB trace or measured capture packet sequence could be obtained. `/proc/asound/card1/stream0` provides ALSA's active playback and advertised capture formats, but is not an on-wire transfer capture. The first restricted-context probe could not open the device; the host-access retry did open it and unexpectedly emitted PCM. No PCM artifact or accompanying URB trace was saved.

## Hardware implications (inference)

A 64-byte FIFO cannot hold one full 196-byte stereo S16/48 kHz service interval packet, so this mode requires streaming/fragmented FIFO handling or an equivalent continuous drain into external buffering. A 34-byte mono S16/16 kHz packet also spans less than a 64-byte FIFO. These are descriptor maxima; actual packets and FIFO service timing were not observed. This analysis does not establish whether a particular USB-host RTL implementation can sustain either mode.

## Host-access retry and selected planning profile

An escalated host query of `arecord -l/-L` found capture card 1 device 0 and the `default:CARD=CODEC`, `sysdefault:CARD=CODEC`, and `front:CARD=CODEC,DEV=0` PCM names. A dynamic VID/PID scan resolved the current sysfs path to `/sys/bus/usb/devices/1-2`. The host ALSA `--dump-hw-params` result reports S8/S16_LE, 1-2 channels, 8-48 kHz, period size 16-48000, and buffer size 32-96000.

The command unexpectedly continued past the hw-parameter print and started emitting capture PCM to stdout for an unknown duration; this behavior and the command are documented in `alsa_capabilities.txt`. The exact arecord process (PID 813689) was terminated with SIGTERM after a follow-up process check found it still active. Subsequent `pgrep` found no arecord process; stream state is capture Stop and playback Running. PCM was emitted to stdout; no PCM artifact was archived. No additional capture has been attempted. This provides ALSA range evidence but not a controlled format-specific capture validation.

The subsequent bounded one-second capture succeeded on native `hw:CARD=CODEC,DEV=0`, stereo S16_LE at 48000 Hz, producing 48000 frames and 192000 PCM bytes. Its command, hash, waveform dimensions and stream-state evidence are in `controlled_capture.json`, with the WAV preserved separately. The selected profile is now validated for native capture on this Linux PC. USB alternate-setting mapping still comes from descriptors/ALSA metadata, and packet-size/timing implications remain inferences because no usbmon trace was obtained. Capture returned to Stop and playback remained Running. `sudo -n` could not grant usbmon access without a password.

## HID report

The HID interface descriptor advertises a 31-byte report descriptor. `lsusb -v` returned `Report Descriptors: ** UNAVAILABLE **`, but a subsequent read-only HID-bus inspection recovered the exact 31 bytes from `/sys/bus/hid/devices/0003:08BB:2902.0001/report_descriptor`. They are preserved in `hid_report_descriptor.bin`, `.txt`, and `.json`. The Consumer-page report advertises Mute (0xe2), Volume Increment (0xe9), and Volume Decrement (0xea), three data bits plus five padding bits. The independent interrupt endpoint is 0x85, maximum one byte, interval 10 ms, as observed in the USB descriptors. No HID event traffic was recorded and no USB driver was detached to read this artifact.
